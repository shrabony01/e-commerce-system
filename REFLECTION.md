# SBA Project Reflection
# 1. How did you implement TypeScript features and OOP principles?
I implemented TypeScript features by defining strict type annotations, utility function signatures, and a dedicated IProductData interface to model the exact shape of the DummyJSON product data. For Object-Oriented Programming, I created a Product class that implements this interface. The class encapsulates core product properties such as id, title, price, discountPercentage, and category. Instead of relying solely on disconnected helper functions, I added instance methods directly to the class: getPriceWithDiscount() to calculate the discounted price using the discount utility, and displayDetails() to format and print product information to the console. This separation kept the code modular, readable, and easy to maintain.

# 2. What challenges did you encounter and how did you overcome them?
My biggest challenge was configuring the TypeScript build pipeline to work seamlessly with modern ES Modules in Node.js. Initially, running npx tsc triggered multiple compilation errors related to CommonJS, verbatimModuleSyntax, and missing type declarations. Additionally, compiled .js, .d.ts, and source map files were generated directly inside the src/ directory instead of staying in dist/. I resolved these issues by adding "type": "module" to package.json, updating tsconfig.json to use "NodeNext" for both module and moduleResolution, ensuring "outDir": "./dist" was properly configured, and switching pure interface imports to import type. After removing the misplaced files from src/, the project compiled cleanly.

# 3. How did you handle asynchronous operations and error management?
I handled asynchronous operations using modern async/await syntax alongside the native Fetch API in apiService.ts. The service asynchronously fetches data from the DummyJSON API and parses the response into typed objects before converting them into Product instances. For error management, I built a custom AppError class that extends JavaScript's built-in Error to track HTTP status codes (such as 404 and 500). I then implemented a centralized handleError utility that catches errors gracefully using instanceof checks. This prevented unexpected network failures—such as querying a non-existent product ID—from crashing the application, while printing clear and informative status messages to the console.
